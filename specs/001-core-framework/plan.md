# Implementation Plan: Core Framework

**Branch**: `001-core-framework` | **Date**: 2026-11-02 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-core-framework/spec.md`

---

## Summary

Build the `rn` ("Rust Native") cross-platform native UI framework. Consumers write
a declarative `ComponentTree` once in platform-agnostic Rust. A reconciler diffs
consecutive trees and emits a minimal `Changeset`. Per-platform renderers apply the
changeset to real native OS controls (AppKit on macOS, Win32 on Windows, GTK4 on
Linux). No platform types leak into consumer code. v0.1 ships a working macOS
renderer with Windows and Linux backends scaffolded.

---

## Technical Context

**Language/Version**: Rust stable 1.75+

**Primary Dependencies**:
- `taffy` — cross-platform Flexbox layout engine
- `objc2` + `objc2-app-kit` — macOS AppKit bindings
- `windows` crate — Win32 controls (Windows backend)
- `gtk4` — GTK4 bindings (Linux backend)
- `crossbeam-channel` — event dispatch between platform loop and app

**Storage**: N/A — no persistent storage

**Testing**: `cargo test`; reconciler tests are headless (no display server).
Platform renderer tests require a display server and run in platform CI jobs.

**Target Platform**: macOS 13+, Windows 10 22H2+, Linux (GTK 4.8+)

**Project Type**: Cargo workspace of library crates

**Performance Goals**: Changeset delivery ≤8ms for a 500-node tree on minimum
target hardware (see constitution). 60fps capable event loop.

**Constraints**: No platform types in public API (`rn` crate). No `unwrap()`/
`expect()` in library code. Reconciler testable headlessly.

**Scale/Scope**: v0.1 — 5 widget types, 3 platform backends (macOS complete,
Windows + Linux scaffolded), 2 example apps, headless reconciler test suite.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-checked post-design below.*

| Principle | Gate | Status |
|-----------|------|--------|
| I. Native-First, Per Platform | macOS=AppKit, Win=Win32, Linux=GTK4. No custom-rendered substitutes. | ✅ PASS |
| II. Stable Trait-Based Public API | `PlatformRenderer` trait defined. Public API in `rn` crate only. Backend crates internal. | ✅ PASS |
| III. Type-Driven Correctness | `ComponentKind`, `Operation`, `EventKind` are enums. `unwrap()` prohibited. Platform types behind trait boundary. | ✅ PASS |
| IV. Render Budget | `taffy` layout + O(n) reconciler targeted at <8ms for 500 nodes. Benchmarks required before merge. | ✅ PASS |
| V. Simplicity / YAGNI | No macro DSL in v1. No reactive signals. No hooks runtime. Builder API only. | ✅ PASS |
| VI. Declarative-Reconciler Architecture | Strict three-layer separation: ComponentTree → Reconciler → PlatformRenderer. Consumer holds no native handles. | ✅ PASS |

**Post-design re-check**: All gates pass. No violations. Complexity Tracking table
not required.

### Source Code (repository root)

```text
Cargo.toml                    # workspace root

rn/                           # public API crate (platform-agnostic)
├── Cargo.toml
└── src/
    ├── lib.rs
    ├── component.rs          # Component, ComponentKind, Props, ComponentTree
    ├── reconciler.rs         # Reconciler, Changeset, Operation
    ├── event.rs              # Event, EventKind, EventPayload, HandlerId
    └── renderer.rs           # PlatformRenderer trait

rn-layout/                    # taffy-backed layout engine (shared)
├── Cargo.toml
└── src/
    └── lib.rs                # compute_layout(tree) -> LayoutResult

rn-macos/                     # macOS AppKit backend
├── Cargo.toml
└── src/
    ├── lib.rs
    └── renderer.rs           # MacosRenderer: PlatformRenderer

rn-windows/                   # Win32 backend (scaffold in v0.1)
├── Cargo.toml
└── src/
    ├── lib.rs
    └── renderer.rs           # WindowsRenderer: PlatformRenderer (stub)

rn-linux/                     # GTK4 backend (scaffold in v0.1)
├── Cargo.toml
└── src/
    ├── lib.rs
    └── renderer.rs           # LinuxRenderer: PlatformRenderer (stub)

examples/
├── hello-world/
│   ├── Cargo.toml
│   └── src/main.rs           # Window + Label + Button demo
└── counter/
    ├── Cargo.toml
    └── src/main.rs           # State change + reconciler demo

tests/
└── reconciler/
    └── tests.rs              # Headless unit tests (no OS required)
```

**Structure Decision**: Cargo workspace with one crate per logical layer. `rn` is
the only consumer-facing crate. Backend crates (`rn-macos`, `rn-windows`,
`rn-linux`) are internal. `rn-layout` is shared across all backends.
